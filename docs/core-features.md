# bookq コア機能仕様

自炊・正規購入など適法に入手した画像（漫画）フォルダを、Tailnet 内のブラウザから読むためのビューア。サーバーは `viewer.py` 1ファイルで完結し、外部ライブラリに依存しない（Python 3.13 標準ライブラリのみ）。この文書はコミット `32b55fb` 時点のコードから起こした仕様で、READMEに載っていない挙動もコードを根拠に記載する。

## システム構成

```
ブラウザ ── HTTPS ──▶ tailscale ── HTTP ──▶ viewer (:8080)
 (Tailnet内)        (TLS終端 + Serve)         Python (viewer.py)
```

Docker Compose で2コンテナを起動する。viewer はホストへのポート公開を持たず、tailscale コンテナが compose ネットワーク内の `viewer:8080` へプロキシする。したがって到達経路は Tailnet 経由の HTTPS のみになる。

| コンテナ | ベースイメージ | 役割 |
| --- | --- | --- |
| `viewer` | `python:3.13-slim` | 画像ビューア + API。`viewer.py` のみを COPY し、`--bind 0.0.0.0 --port 8080` で起動する |
| `tailscale` | `tailscale/tailscale:latest` | Tailscale ノード。userspace networking で `tailscaled` を起動し、`tailscale serve --bg http://viewer:8080` で HTTPS(443) 公開する |

画像の実体はホスト側の画像フォルダ（`DOWNLOADS_HOST_DIR`、既定は `./downloads`）を `/app/downloads` にマウントして参照する。Tailscale の認証状態は `tailscale-state` ボリュームに永続化され、再起動時は authkey を使わず hostname の更新だけを行う。

## サーバー仕様（viewer.py）

### 起動オプション

| オプション | 意味 | 既定値 |
| --- | --- | --- |
| `-p, --port` | 待ち受けポート | 8080 |
| `-d, --downloads` | 画像ルートディレクトリ | スクリプトと同階層の `downloads/` |
| `-b, --bind` | バインドアドレス | `127.0.0.1`（Docker では `0.0.0.0` を指定） |

起動時に downloads ディレクトリの存在を確認し、なければ exit 1 する。サーバーは `ThreadingMixIn` を混ぜた HTTPServer（デーモンスレッド、`request_queue_size=128`）で、リクエストごとにスレッドを立てる。同時リクエストで 502 が出た問題への対処として導入された（コミット `38cd9b7`）。

### HTTP API

| エンドポイント | 応答 |
| --- | --- |
| `GET /api/health` | `{"status": "ok"}` |
| `GET /api/folders` | downloads 直下から再帰走査したフォルダツリー（JSON、構造は後述） |
| `GET /api/images?folder=<path>` | 指定フォルダ直下の画像ファイル名の配列。`folder` 欠落は 400、範囲外パスは 403、非ディレクトリは 404 |
| `GET /image/<folder>/<file>` | 画像ファイル本体。最後の `/` でフォルダとファイル名に分割する |
| `GET /` `/index.html` | ビューア HTML（`INDEX_HTML` 定数に埋め込まれた単一ページ） |
| その他のパス | `SimpleHTTPRequestHandler` にフォールバックし、downloads 配下を静的配信する |

HTML と API は `Cache-Control: no-cache`、画像は `public, max-age=3600` を返す。全応答に `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin` を付ける。アクセスログは 200 以外のみ stderr に出す。

### フォルダツリーの生成規則（scan_tree）

`/api/folders` はリクエストのたびに downloads をフルスキャンする（キャッシュなし）。ノードは `{"name", "type": "folder"|"image", "children"}` で、folder ノードには `thumb`（サブツリー内で最初に見つかる画像の相対パス）と、条件を満たす場合のみ `thumbs`（直下サブフォルダの thumb を最大9件。2件以上あるときだけ付く）が加わる。

走査には次の規則がある。

- 対象拡張子は `.avif` `.webp` `.jpg` `.jpeg` `.png` `.gif` `.bmp` `.svg`。ドット始まりのファイル・ディレクトリは無視する
- ファイル名・ディレクトリ名とも自然順ソート（名前中の数値列を数値として比較。`01 < 02 < 10`、`ch-2 < ch-10`。同名の数値列で並ぶ場合のみ辞書順で決着。漢数字も数値スロット（「第X部」「第X話」等）では数値として扱う（例: `第一部 < 第二部 < 第十話`。固有名詞中の漢数字は変換しない））
- 画像を1枚も持たず、サブディレクトリがちょうど1つのフォルダはフラット化する。子の内容を親に繰り上げ、`name` を `親名/子名` に連結する。深い一本道の階層が UI 上は1行に潰れる
- アーカイブ（`.zip`/`.cbz`/`.rar`/`.cbr`/`.epub`）は仮想フォルダとして扱い、`MAX_ARCHIVE_ENTRIES=2000`（`app/archive.py:28-29`）を超えるエントリは一覧から切り捨てられる
- 2000件超の書庫は巻ごとに分割して配置する（例）:
  `7z x big.rar -obig && 7z a vol1.zip big/vol1 && 7z a vol2.zip big/vol2`
  分割後のzipをdownloads配下に置く（マルチボリュームrarのまま置かない）
- 分割はスキャン/応答の高速化にも効く。`/api/folders`は毎回フル再列挙し、`/api/images`のprefix指定も都度`list_archive_entries`を呼び直す（`app/routes.py:500`）

### 画像配信

`/image/` は `resolve()` 後のパスが downloads ルート配下にあることを文字列前方一致で検査し、外れていれば 403 を返す（`/api/images` も同じ検査を行う）。Content-Type は `mimetypes` で拡張子から推定し、不明なら `application/octet-stream` にする。ファイルは全量を read してから書き出す方式で、Range リクエストやストリーミングには対応しない。

## ビューア UI（単一ページ、vanilla JS）

### サイドバー（フォルダブラウズ）

タイル表示（既定）とリスト表示をフッターのボタンで切り替える。タイル表示ではサイドバーが全幅になる。共通の挙動は次のとおり。

- フォルダをタップしたとき、そのフォルダの子がすべて画像なら閲覧を開始し、そうでなければ1階層ドリルダウンする。ヘッダーの `↩` で親階層へ戻る
- 検索ボックスは「現在表示中の階層」のフォルダをフルパス部分一致（小文字化）で絞り込む
- 階層を戻ったときのために、パスごとにスクロール位置を保存・復元する
- フォルダを開いたときの一覧の位置は次の順で決まる: ①ビューアから戻ったときはビューアで表示していたページのあるエピソードを上端に、②その階層の保存位置がある復帰（`↩`/Back）は保存位置を復元、③それ以外の新規オープンは直下の既読エピソードのうち一覧順で最後（＝最大番号）を上端に、④該当なしは上端。ルート（作品一覧）は①③を使わない（「続きから」ボタンの役割）。判定は `app/static/browse/scroll.js`（`window.BrowseScroll.decide`）が一元管理し、決定は level に紐づく intent として保持（☰ 復帰では `restoreBrowse` が 2 回走り、タイルtap 直後にも `history.go(-1)` 経由の復帰が来るため、同じ答えを冪等に返し古い保存位置に上書きさせない）。描画側は `renderBrowse({scrollAnchor})` で `#tile-grid` の `innerHTML` 置換と同一タスクで適用する
 - 上端のpull-to-refreshはSafari標準に委譲する（独自の60px再読み込みは廃止）。ブラウザ自体のpullでページが再読み込みされる。下端では最大18pxのラバーバンド抵抗を残す。左右スワイプで1階層戻る（60pxでready、48pxまで戻せばcancel）はiOS設定アプリ準拠

タイルのサムネイルは、サブフォルダを2つ以上持つフォルダでは複数サムネイルのグリッドになる。件数ごとのレイアウトは 2〜3件が縦積み1列、4件が2×2、6件と9件が3×3、5件と8件が span 調整付き3列、7件が 2-3-2 の3行になる。単一サムネイルは `object-fit: cover` の 2:3 固定比で表示する。

### ページ表示と操作

漫画向けの右→左読みを前提に、ページを横一列のストリップとして絶対配置し、`translateX` で送る。操作は次の3系統がある。

| 操作 | 割り当て |
| --- | --- |
| タップゾーン | 画面左45% = 次ページ、中央10% = ツールバー表示切替、右45% = 前ページ |
| キーボード | `←` 次ページ、`→` 前ページ、`F` サイドバー開閉、`Home` 先頭、`End` 末尾、`Esc` サイドバーを閉じる |
| スライダー | RTL 配置で右端が1ページ目。ドラッグで任意ページへ移動する |

スワイプは指追従で、縦横 8px 動くまで方向を判定せず、縦と判定したらネイティブスクロールに委ねる。離した位置が閾値 `min(画面幅の10%, 70px)` を超えていればページを送り、端では 0.35 倍のラバーバンド抵抗をかける。速度が 0.05px/ms を超えるスワイプはモメンタムスクロールになり、`実移動距離 × 1.3 + 速度 × 500` から送りページ数を算出して一気に送る（アニメーション時間は 0.25s + 0.15s/ページ、上限 1.5s）。

### 見開き表示（横向き）

画面が横長のとき、既定で2ページ見開き（`2P`）になり、右上のボタンで1ページ表示と切り替えられる。見開きのセル幅は最初に読み込めた画像の縦横比から `画面高 × 幅/高` で実測し、以後のページに適用する。

`◀`（spread-shift）ボタンはページの組み方をずらす機能で、`spreadOffset` を 0/1 でトグルする。1 のときは先頭ページ（表紙）を単独で中央表示し、以降を (1,2)(3,4)… と組む。奇数末尾など相方のいないページも単独で中央表示する。ページ送りは見開き時2ページ刻み、ソロページ区間は1ページ刻みになる。画面回転・リサイズ時は向きを再判定してレイアウトし直す。

### ページ読み込み管理

`<img>` 要素はページごとに遅延生成し、現在ページの前後だけを保持する。

| パラメータ | 値 | 意味 |
| --- | --- | --- |
| `PREFETCH_AHEAD` | 8 | 進行方向に先読みするページ数 |
| `PREFETCH_BEHIND` | 3 | 戻り方向に保持するページ数 |
| `EVICT_AHEAD` / `EVICT_BEHIND` | 14 / 6 | この範囲を超えた DOM ノードを破棄する |

モメンタムで複数ページ飛ぶ場合は、通過区間の全ページを事前生成してから送る。現在ページの読み込み完了でスピナーを消し、読み込み失敗はカウンタに `⚠` を付けて表示する。

## 制約・注意点

- 認証・認可はアプリ自体には一切なく、Tailnet 内からしか到達できないことだけが防御線になる。`TS_AUTHKEY` の管理がそのままアクセス制御を意味する
- フォールバックの静的配信により、downloads 配下であれば画像以外のファイルやディレクトリリスティングも配信される
- パス検査は `resolve()` 後の文字列前方一致で、区切り文字を含めない比較のため、ルートと同じ接頭辞を持つ兄弟ディレクトリ（例: `downloads2`）があれば通過しうる。Docker 運用ではマウント構成上、実害の出る配置になっていない
- 画像とサブフォルダが混在するフォルダでは、フォルダ内の一覧にはサブフォルダのみが表示され、直下の画像は一つ上の階層にそのフォルダ用の images-tile（このフォルダを読む）1 枚として表示される。images-tile をクリックするとそのフォルダの直下画像のみをビューアで開く。例外としてルート直下の画像には親階層が存在しないため、ルートの一覧にのみ self-tile（同じ文言）が表示される
- `/api/folders` は毎回フルスキャンするため、フォルダ数が増えると応答時間が伸びる
- docker-compose.yml のマウント元パスはハードコードされており、他ホストで使う場合は書き換えが必要になる
- compose の viewer に `ports` 定義がないため、prd.sh のヘルスチェック（`http://localhost:8080/api/health`）はホストから到達せず、30秒のタイムアウトまで待ってから成功表示なしで先へ進む
