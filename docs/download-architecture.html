ダウンロード機能の実装整理PR #59 OPEN

ローカル画像ビューア bookq のオフライン保存（自動キャッシュ＋明示的ダウンロード／削除）の全体像

参照: app/static/offline-core.js · app/static/app.js · app/static/sw.js · PR #59

前提: ブラウザ内で完結する 3 層構造（UI / 実行 / ストレージ）。サーバー側は画像配信 API を提供するだけで、ダウンロード処理には関与しない。§6 はマージ後の姿、それ以外は現行ベースラインで共通。

01全体アーキテクチャ

UI 層（ボタン・状態表示）→ 実行層（downloadWork / deleteWork）→ ストレージ層（IndexedDB + Cache API）。Service Worker は閲覧時のキャッシュヒットを担い、自動キャッシュはここで自然に発生する。

ファイル役割原則
offline-core.jsIndexedDB ラッパ OfflineStore、encodePath/imageUrl/cacheNameFor/fmt/dedupedBytes を window.OfflineCore として公開単一情報源。app.js と harness が両方消費。二重実装禁止

offline-harness.htmlQA 用可視化（caches / IDB / storage）同じ OfflineCore を読むので報告が嘘をつかない

02ダウンロードパイプライン（downloadWork）

親フォルダを指定しても leaf 単位に分解して 1 レコードずつ保存する（list_images は再帰しないため）。ダウンロードは逐次実行（並列化は意図的に見送り）。

    style F fill:#3a2226,stroke:#c05b5b,color:#e8c9c9
    style Q4 fill:#3a2226,stroke:#c05b5b,color:#e8c9c9
  • URL 生成は encodePath 1 箇所のみ — パスセグメントごとに encodeURIComponent し / は残す。ビューア・サムネ・DL のキャッシュキーが完全一致しないと caches.match（完全一致）でヒットしない。
  • clone の消費順 — cacheClone を先に put し、sizeClone でサイズ取得。逆だと iOS（Content-Length 欠損環境）で bytes が 0 になる。
  • addedAt は再 DL でも維持 — LRU 退避（Safari 7 日対策）の対象期間を保つため。

  • レコード粒度＝leaf ごと 1 件（＋直下画像を持つフォルダ自身）。例：group/episodes/ch-1〜ch-11 なら 4 件。
  • byte 合計の二重計上対策 — dedupedBytes() が「子孫レコードを持つ親レコード」を除外して合算。harness の raw sum vs dedup sum 比較で検証される。
  • Safari 7 日自動削除対策 — 起動時にキャッシュ 1 件 touch（LRU 対象外へ）、初回ジェスチャで navigator.storage.persist()（リスナは {once:true}）。

05Service Worker のリクエストルーティング

自動キャッシュは CacheFirst が担う — ビューアで開いたページ＋先読み窓（PREFETCH_AHEAD=8）が自然にキャッシュへ溜まる。明示的 DL との違いは quota 超過時の挙動だけ（自動＝黙って諦める／明示＝確認ダイアログ）。

  • 6 表示モード（tile / list / card × 通常/検索）すべてで同一の委譲リスナ 1 本が振り分け。ボタンと popover は実 <button> なので Enter / Space のネイティブ活性化で操作できる。
  • quota 超過時の明示 DL はアプリ内モーダル showQuotaConfirm()（「削除して続行」/「キャンセル」）で再試行。window.confirm は廃止。成功トーストは中立色、エラーは赤、オフライン表示は琥珀色（#c9a24f）。
  • 削除は従来どおり2タップ確認（_confirmMap）＋ DELETING ロック（_deletingSet）。Undo なし。
  • sw.js と offline-core.js は無変更（ガードレール厳守）。
  • テスト: test_download_button.py（新規 6 件）＋ test_offline.py（文言移行）＋ test_offline_harness.py（10 件維持）。

  • leaf 列挙ルール: 画像のみのフォルダ → 自身が leaf ／ 子フォルダあり → 子孫 leaf を集約 ／ 直下画像もあればそれも追加。
